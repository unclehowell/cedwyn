Add a section

A new web app on its own branch, with its own data, reachable from the header selector.

  • Steps
  • After that

A section is added without touching any other section. Worked example: nft-art, a gallery of digital editions made from non-human images in the Wayback Vault records.

Steps

  1. Pick an id. Lower-case, unique in themes.json, used as the path: nft-art → /nft-art/.
  2. Create the branch. A new branch holding the web app: public/index.html, styles and scripts. Layout only: no record text in the templates.
  3. Add the section's data. Records go in data/ on the branch as JSON (for nft-art: one record per artwork with id, title, caption, source record id, edition, price, image path). The page renders from this data in the browser, or a build command renders it at build time.
  4. Point at core records, do not copy them. Each artwork carries the id or sha256 of the core artifact it was made from; the page reads that artifact from the core catalogue (Cedwyn.db(), /_blob/<sha>) instead of keeping its own copy.
  5. Register it. One entry in themes.json on main, through a pull request labelled site-wide: 
    {
  "id": "nft-art",
  "title": "The Garden Gallery",
  "cy": "…", "es": "…",
  "live": "https://cedwyn.bucklerfamily.estate/nft-art/",
  "hosts": [], "paths": [],
  "branch": "nft-art", "dir": "public",
  "group": "interactive"
}
    The position of the entry in the themes list is its position in the header selector.
  6. Build. Merging the pull request starts build-cedwyn. The section is copied to /nft-art/, its files enter the core catalogue under theme = 'nft-art', the header selector gains the new stop, and the export writes /db/export/sections/nft-art.json.gz.
  7. Check. Open /nft-art/ at phone width, step through the selector to reach it, and query it: SELECT count(*) FROM locations WHERE theme = 'nft-art'.

After that

  • Changes to the section are pushes to its own branch; each push is picked up by the next build. Nothing on main changes.
  • To take the section out, remove its entry from themes.json; the branch stays.
  • To make it a standalone site later, point a separate Pages project at the same branch and folder.
  • A section with live writes (orders, comments) keeps a small store of its own and publishes a JSON file the build reads; see Federation.
