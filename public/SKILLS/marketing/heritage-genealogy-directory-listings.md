# Free heritage and genealogy directory listings (backlinks with no outreach)

Written 26 Oct 2026 for Cedwyn (cedwyn.bucklerfamily.estate). Each route below is a public submission form or an open wiki edit. None of them involves emailing or messaging a person. Nothing in this file was submitted; it is a how-to.

## What the evidence shows
- **Cyndi's List** (cyndislist.com, read 26 Oct 2026) has "more than 317,000 genealogy links" in "more than 200 categories" and has run since 1996. It takes new links through a public form. The form's rules, verbatim in substance: genealogy links only ("non-genealogical links ... are deleted before they are ever seen"); the title must be entered "exactly as shown on the web site", with surnames in UPPERCASE; a short one-paragraph description naming the place (city, county, country); 10–15 surnames at most, comma-separated; one contact email.
- **GENUKI** (genuki.org.uk) is run by a registered charitable trust. Its Glamorgan pages are "maintained by Team Wales" with volunteer help. Every page has a "Report problems or contribute information" link, and there is a public contact form at genuki.org.uk GENUKI's Glamorgan page lists local societies and journals (e.g. the Gower Society) with a one-line description each, so an archive of dated parish-level records fits its format. (Read 26 Oct 2026.)
- **FamilySearch Research Wiki** has a page for most Glamorgan parishes ("Cardiff, Glamorgan, Wales Genealogy", "Pen-marc, Glamorgan, Wales Genealogy" etc., search results 26 Oct 2026), each with record sections and outside links. It needs a FamilySearch account, which is personal (see the rule below). This box was blocked from reading it (HTTP 403), so the wiki's own external-link rules are **not read here**; read them before any edit. A separate FamilySearch rule bans external links in uploaded PDFs (reported on r/Genealogy, May 2025), so do not rely on uploads for links.
- **WikiTree Free Space / Wales Project**: already in the project workspace (#25) and GROUPS.md. WikiTree's honour code is signed by a person, so it is for the project lead's own account only.
- **Society for One-Place Studies** (one-place-studies.org) keeps a "Registered Studies" list. Registration appears to be through membership (its registration page returned 404 on 26 Oct 2026). A "Llandough one-place study" would fit, but this is a members' route and is **not checked**.
- **Curlie** (the old DMOZ volunteer directory) returned 503 on 26 Oct 2026. Treat it as unavailable.

## How to do it (once per directory, no repeats)
1. **Pick one landing URL per directory.** Use the page that best fits the directory's topic, not /ebooks/. For a genealogy list that is the parish or people index (an evidence page listing dated records with sources). A directory that sees a shop page as the target rejects it.
2. **Write the listing in the directory's own format.** Use the page's exact title. Write one factual sentence: place, date range, record types, e.g. "Dated land, parish and court records for Llandough and Cogan, Vale of Glamorgan, Wales, 1600s–1900s, with sources." Add surnames in UPPERCASE only where the form asks for them. Use none of the banned public words, never name the project lead, and include no insignia.
3. **Submit through the public form only**, from [address kept in the project workspace] or Tab's own mail. Never write to a volunteer's personal address. Keep a log row: directory, date, URL submitted, text used, status.
4. **Wait, then check.** These are volunteer-run. Check once after 30 days whether the link is live (search the directory for the domain). Never resubmit the same URL; a resubmission reads as spam.
5. **Wiki routes (FamilySearch, WikiTree) need a personal account.** Only the project lead can do them, from his own account under its honour code and conflict-of-interest rules: add a link in the parish page's "websites" or "records" section, only where it adds a record type the page lacks.
