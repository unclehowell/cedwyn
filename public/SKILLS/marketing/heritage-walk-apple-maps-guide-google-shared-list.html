Heritage walk as a shareable map list: Apple Maps Guide + Google Maps shared list

date: 2026-11-01 (skills harvest ~00:30Z). topic: publish the heritage walk's stops as a user-made Apple Maps Guide and a Google Maps shared list, so a visitor saves the whole walk into the map app they already use, from one link or QR. Free. Different from apple-business-maps-showcases-branded-mail.md (business place card) and google-maps-gbp-demolished-heritage-site.md (business profile): this is a list of places made by a user account. Status for Cedwyn: proposal (a public list under an account needs the owner's GO).

What the sources show (read unless marked)

  • Apple Support, "Organize places with custom guides in Maps on iPhone" (iOS 27 edition, read). Your Guides > + > name the guide, optional cover image from your photos; add any place from its place card ("Add to Guides"); share from the guide's Share button; edit (rename, cover, remove places); Publisher Guides can also be saved into your guides.
  • Apple Support, "Explore places with guides" (snippet). Publisher Guides are Apple-curated; a destination needs to be an Apple-vetted publisher. A third-party agency page (Odyssey Studios, snippet only, page blocked) puts vetted publishers at "fewer than 125". So a small project uses a user Guide, not a Publisher Guide.
  • gotoapplemaps.com "How to share Apple Maps Guides" (Sept 2026, read; third-party tool site). A shared Guide link looks like `maps.apple.com it opens in Maps on iPhone/iPad/Mac and in Apple Maps on the web on Android/Windows; needs iOS 14+; anyone with the link can open it. Their free "Guide Decoder" turns a Guide link into Google Maps links + CSV, and a Google Takeout export into a Guide. Third-party tool: useful, not needed.
  • Google Maps Help, "Create a list of places" (read). You > New list > name + description; type Private or Shared (share a link to view or edit); custom icon; custom order ("Customize list order"); add a note per place; collaborators can be invited (and then their names show). The view link is what we share.
  • Numbers: StatCounter UK mobile OS share Sept 2025-Sept 2026: iOS 46.97%, Android 53.02% (snippet from gs.statcounter.com, not opened). So either list alone misses about half of UK phones; publish both. No figure found for saves or opens of a user Guide/list; any numbers we report are our own (redirect clicks).

The method, step by step

  1. Only real map places. Each stop must be a place the map knows (a church, a pub, a named road point) or a dropped pin; check each stop appears correctly in both apps before publishing. Use pins for a lost building's site and say so in the note.
  2. Build the Apple Guide on an account the project controls: title "Llandough heritage walk", cover image we hold rights to, stops added in walking order (Guides do not show route order, so number the stop names "1. ...").
  3. Build the Google shared list with the same names, custom order, one-line note per stop (record + date), list description with the site page name (Google notes show plain text; keep it neutral).
  4. One short link per list through our own redirect (so clicks are counted), plus one QR on the walk leaflet, table cards and the walk page: "Save the walk to your maps: Apple | Google".
  5. Accessibility and honesty: state distance, surface and that some stops are sites of lost buildings on private land, view from the road only.
  6. Review quarterly: re-open both links on a phone; fix any stop the map has moved or merged.

How we apply it to Cedwyn

  • Stops come from the live walk route only (Wales scope pages); each note carries one record line from the evidence pages. Llandough Farm is not Great House Farm; the Whitchurch Tŷ Mawr is a different place and never appears. Tymawr is a confirmed variant name and may appear in a note.
  • No stop on private land as a destination: use a roadside pin and "view from the road".
  • The account: a project-owned Apple ID / Google account (owner decides which; nothing is created without GO). The account display name must not be a family member's name; never name the owner or living descendants.
  • The site stays outbound-link free: on the walk page the save buttons go through our own internal redirect path, and the leaflet/table card QR goes to that path. If the internal-links rule rules out even a redirect to maps.apple.com / google.com, keep the lists for print and messages only.
  • Pairs with: local-business-sponsor-a-stop-printed-walk-leaflet.md and cafe-pub-history-placemats-table-cards.md (QR surfaces), then-and-now-rephotography-same-spot-posts.md (same stops).
  • Gates: making the lists public, the account choice and any redirect on the site need the owner's GO; HubSpot draft task only; zero spend.
  • Next action (no GO needed): write the stop table (name as shown in each app, lat/long, note text, private-land flag) as a CSV in the project workspace, plus a HubSpot draft task "[BIZDEV] Walk: Apple Guide + Google list (draft)".
