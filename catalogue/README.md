# Cedwyn forensic catalogue data model

This directory is the maintained, version-controlled intake register for the central catalogue. It supplements (and does not replace) the byte-level archive, full-text index, locations, and graph generated by `tools/build_db.py`.

## Keep four things separate

1. **Source record** (`sources.json`): describes a source that has been located, or a page/source lead whose relevance is not yet confirmed. The description answers *what this item is and contains*. It must not smuggle an interpretation into the source description.
2. **Interpretation** (`interpretations.json`): an analyst's reading of one or more sources. It must cite source IDs and precise pinpoints, state what the cited material supports and does not establish, record contrary material, and state what would confirm or refute the reading. “Speculative/interim” is an acceptable status when expressly labelled.
3. **Expected/missing artifact lead** (`expected-records.json`): a retrieval target, not a located record. Every entry must have `not_a_located_record: true`, an explicit search scope/status, a reason the item is sought, propositions it could support, and plausible alternative outcomes. Custodians are candidates until verified. “Not located in the searched scope” must not be rewritten as “not held”, “destroyed”, or “concealed”.
4. **Monitored public page** (`monitored-pages.json` plus `monitoring/state.json` and `history.jsonl`): a URL whose public response is hash-checked. A Wayback calendar URL is only a search interface; a snapshot is “confirmed” only where the actual snapshot URL/timestamp is recorded. A changed digest is an alert, not a finding about motive.

## Provenance minimum

For each email disclosure or attached file, keep a separate row per attachment and preserve the email's sent/received dates, sender, recipient, subject, disclosure reference, original filename, exact file hash, and completeness/read status. Do not merge distinct attachments merely because their contents are similar. Copies and mirrors of one original share an `independent_origin_id`; a repeat copy does not count as independent corroboration.

For public pages, retain the canonical URL, best verified archived snapshot (when available), and a Wayback calendar URL. A transcription or excerpt is explicitly labelled as such. Public institutional records, family testimony, contemporaneous press, later official records, secondary commentary and analytical inference are different source classes.

## Build and check

```sh
python3 tools/validate_catalogue.py
python3 tools/monitor_sources.py --dry-run
```

The build imports these files into the SQLite database as `source_records`, `interpretations`, `research_leads` and `monitored_pages`. The catalogue UI exposes these registers separately. This is designed to keep speculative research moving while making it impossible to mistake a speculative lead for a located artifact.

## Initial-state caution

The initial entries are a starting point, not a claim that the full audit is complete. The BP judgment page has been located and read in part; the judgment's original sealed file and underlying documents remain distinct retrieval targets. Hansard is only a relevance-unconfirmed lead until the target column has been checked. The missing-record register is intentionally populated from the supplied forensic research specification, with all entries explicitly marked as not located in this work session.
