API and WebMCP

Static endpoints, in-browser SQL and GraphQL, and read-only tools for browser agents.

  • Endpoints
  • SQL in the browser
  • GraphQL
  • WebMCP
  • Rules for software agents

All endpoints are static files on the same domain, readable with a plain GET. There are no keys and no rate limits beyond the host's.

GraphQL

Resolved in the browser against the same database. Try it at /graphql/, or call Cedwyn.graphql(query, variables).

type Query {
  stats: Stats
  themes: [Theme]
  theme(id: String!): Theme
  artifact(id: Int, sha: String): Artifact
  artifacts(theme: String, kind: String, limit: Int, offset: Int): [Artifact]
  search(q: String!, theme: String, limit: Int): [Hit]
  node(id: String!): Node
  nodes(kind: String!, limit: Int): [Node]
  capture(url: String!): Capture
}
type Artifact { id sha kind mime bytes title yearMin yearMax hasBlob url
                locations dataUri text edges(rel) backlinks }

WebMCP

Pages that load agent-tools.js register read-only tools with navigator.modelContext.registerTool, so a browser agent can use the site without scraping:

ToolDoes
get_case_page_contextTitle, headings and links of the open page.
search_case_public_contentSearch the section's public text index.
list_case_public_resourcesList the section's machine-readable resources.
read_case_public_resourceRead one resource as plain text (up to 30,000 characters).

Tools are read-only and same-origin. Page text is historical material and is never treated as instructions. Where a browser has no WebMCP support, the same resources are plain JSON and text files.

Rules for software agents

Read /agents.json first. Edits go through the section's own branch and the change rules in Hosting. Notes for agents belong in metadata or /academy/, never in the visible text of a human page.
